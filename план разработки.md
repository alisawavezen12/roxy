# План разработки и обучения

Порядок построен так, чтобы после каждого этапа был работающий и проверяемый результат. Сначала собираем минимальный backend, затем подключаем frontend и постепенно добавляем реальные возможности проекта.

## Этап 1. Минимальное окружение

Цель — запустить проект локально и получить предсказуемую среду разработки.

- [ ] Создать базовую структуру проекта
- [ ] Подготовить Docker Compose
- [ ] Добавить PostgreSQL
- [ ] Добавить MinIO
- [ ] Настроить переменные окружения
- [ ] Настроить сети, volumes и healthcheck
- [ ] Проверить запуск и остановку всех контейнеров

**Результат:** локальное окружение запускается одной командой, сервисы видят друг друга.

## Этап 2. Минимальный backend на Wisp и Mist

Цель — понять устройство web-приложения и получить первый HTTP API.

- [ ] Создать backend на Wisp
- [ ] Настроить Mist как HTTP-сервер
- [ ] Добавить простой endpoint healthcheck
- [ ] Разобраться с роутингом
- [ ] Добавить JSON-ответы и обработку ошибок
- [ ] Настроить базовую структуру модулей
- [ ] Проверить API через `curl`

**Результат:** backend запускается в контейнере и отвечает на HTTP-запросы.

## Этап 3. PostgreSQL и первая вертикальная фича

Цель — пройти полный путь от HTTP-запроса до сохранения и чтения данных.

- [ ] Спроектировать минимальные таблицы пользователей и постов
- [ ] Добавить миграции
- [ ] Подключить PostgreSQL через `pog`
- [ ] Выполнять параметризованные запросы
- [ ] Реализовать создание поста
- [ ] Реализовать получение списка постов
- [ ] Добавить базовую валидацию входных данных
- [ ] Проверить сценарии через `curl` и SQL

**Результат:** можно создать пост через API и получить его обратно из базы.

## Этап 4. Frontend на Lustre

Цель — подключить настоящий интерфейс к уже работающему API.

- [ ] Создать frontend на Lustre
- [ ] Разобраться с Model / Message / Update / View
- [ ] Реализовать состояние страницы
- [ ] Обработать события DOM
- [ ] Подключить HTTP-запросы к backend
- [ ] Сделать страницу со списком постов
- [ ] Сделать форму создания поста
- [ ] Добавить базовый роутинг
- [ ] Собрать frontend в JavaScript

**Результат:** посты можно просматривать и создавать через браузер.

## Этап 5. Основные сущности и авторизация

Цель — перейти от демонстрационного API к основе социальной сети.

- [ ] Добавить пользователей и страницы
- [ ] Подключить авторизацию через SSO
- [ ] Разобраться с OAuth2 / OIDC на уровне интеграции
- [ ] Реализовать backend-сессию через HttpOnly cookie
- [ ] Добавить проверку прав владельца
- [ ] Реализовать страницу пользователя
- [ ] Добавить удаление собственного поста
- [ ] Добавить поиск пользователя по нику

**Результат:** пользователь может войти, открыть свою страницу и управлять своими постами.

## Этап 6. Файлы и функционал постов

Цель — добавить реальные данные, которые нельзя хранить только в PostgreSQL.

- [ ] Подключить MinIO как S3-compatible storage
- [ ] Реализовать загрузку изображений
- [ ] Использовать presigned URL
- [ ] Добавить изображения к постам

**Результат:** пост поддерживает текст, изображения, комментарии и реакции.

## Этап 7. Webhooks и фоновые задачи

Цель — освоить интеграции и OTP-подход к задачам, которые не должны блокировать HTTP-запрос.

- [ ] Создать incoming webhook
- [ ] Проверять secret и валидировать payload
- [ ] Преобразовывать входящее событие в пост
- [ ] Изучить actors и обмен сообщениями
- [ ] Создать supervisor для фоновых задач
- [ ] Создать outgoing webhook
- [ ] Добавить retry при ошибке доставки
- [ ] Сохранять историю попыток

**Результат:** внешние сервисы могут создавать посты, а приложение — отправлять события наружу.

- [ ] Спроектировать сущности доски и объектов
- [ ] Подключить WebSocket через Mist
- [ ] Обрабатывать подключение и отключение клиента
- [ ] Реализовать синхронизацию состояния доски
- [ ] Передавать создание объекта
- [ ] Передавать перемещение объекта
- [ ] Передавать изменение размера объекта
- [ ] Передавать удаление объекта
- [ ] Добавить переподключение клиента

## Этап 9. Бинарный протокол

Цель — применить бинарный формат там, где он действительно уместен: в событиях WebSocket-доски.

- [ ] Определить формат сообщения
- [ ] Добавить тип, версию и идентификатор сообщения
- [ ] Реализовать бинарные события доски
- [ ] Обработать неизвестные типы и версии
- [ ] Оставить обычный HTTP API на JSON
- [ ] Сравнить бинарный формат и JSON по размеру и скорости

**Результат:** realtime-события доски используют отдельный версионируемый бинарный протокол.

## Этап 10. Frontend-интеграции и производительность

Цель — изучить дополнительные возможности frontend после появления реальной задачи.

- [ ] Подключить JavaScript-функции из Lustre

- [ ] Подключить WebSocket к frontend
- [ ] Реализовать интерфейс доски
- [ ] Выбрать реальную CPU-intensive задачу

- [ ] Скомпилировать её в WebAssembly
