# О продукте

Соц сеть, даже скорее блог самый простой функционал, но красивый и хорошо спроектирован технически

## Фичи

- авторизация через мой sso
- стена постов
- стена как мирро (отдельная)

## Стек кратко

docker
Frontend → Gleam + Lustre
Backend → Gleam + Wisp + Mist + BEAM
Database → PostgreSQL
Files → S3-compatible storage (MinIO dev / R2 prod)
Realtime → WebSocket + OTP
Balancing → HAProxy
WASM → Rust
Tooling → jq + Bash + SQL

## Функционал

- написать пост (себе на страницу, фото, текст, эмодзи)
- найти пользователя по нику
- посмотреть страницу пользователя (переключать 2 его страницы, радиокнопка)
- добавить картинку/текст на свою доску миро
- поставить звездочку странице
- поставить реакцию на пост (любой)
- оставить коммент на пост (любой, можно вкл галочку и анонимно поставить, даже мы не узнаем тогда кто оставил коммент)
- поделиться постом - ссылка на пост - при открытии пост на фул экран
- владелец может удалить пост
- в настройках можно настроить веб хук для генерации постов (если что-то прилетело - описать как из этого делаем пост)

## общее

А вебхуки я бы сделал сразу в обе стороны:

Incoming webhook
→ внешний сервис прислал событие
→ валидируем secret
→ преобразуем payload по настройке
→ создаём Post

Outgoing webhook
→ произошло событие в соцсети
→ ставим delivery в background job
→ POST на URL пользователя
→ retry при ошибке
→ сохраняем историю попыток

Бинарный протокол я тоже не стал бы использовать для всего API. HTTP API пусть остаётся обычным JSON. А вот WebSocket доски:

move object
resize object
create object
delete object
cursor position

Например у тебя Miro-подобная доска. Представим, что со временем там:

десятки тысяч элементов;
вычисление layout;
spatial queries;
массовые преобразования координат;
обработка изображений;
какие-нибудь simulation/physics;
генерация превью.

Можно сделать:

↓
WASM / native boundary
↓
Futhark GPU computation
